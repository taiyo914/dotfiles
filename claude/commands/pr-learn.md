PR $ARGUMENTS の review を、@~/dotfiles/claude/commands/learn.md の手順で手伝う。「タスク」は「この PR の review」と読み替え、次の点だけ変える。

- ファイル名
    - `YYMMdd_PR_<PR番号>.md` と `YYMMdd_PR_<PR番号>_report.md` にする。
- レポートの最初の項目
    - 「この PR の種類と、reviewer として見るべき観点。なぜその観点なのか」にする。
    - サブエージェントには PR の差分だけでなく、関連するコードも調べさせる。
- セッションで言わないこと
    - どこを見るべきか、どこが気になる点かも言わない。
- ヒントの1段階目
    - 見るべき観点の名前だけにする。
- 答え合わせのあと
    - 学んだ観点を、PR の種類ごとの review 観点のノートに追記することを提案する。追記する前に差分を見せて了承をもらう。
