# グローバルルール

## ツールのインストール

パッケージやツールのインストールは絶対に自分で実行しない。必ずユーザーにやらせる。

対象は環境に永続的な変更を加えるものすべて。

- brew install / tap / trust / uninstall / upgrade
- npm -g、yarn global、pnpm -g
- pip、gem、cargo install、go install
- その他、システムやユーザー環境にファイルを残すインストーラ

必要になったら、コマンドを提示して「`! <コマンド>` で実行してください」と伝えて待つ。
勝手に入れて事後報告してはいけない。作業が途中で止まっても構わない。

## ファイルの編集

ファイルの作成や変更には Edit ツールか Write ツールを使う。sed やヒアドキュメントなどの Bash コマンドでファイルを書き換えない。Bash で変更した内容は /rewind でコードを元に戻せないため。

ただし、大量のファイルの一括置換は Bash を使ってよい。

## 言葉づかい

中学生でもわかるようにわかりやすく書く。

日本語で書くとき、比喩・擬人化・一般的でない言い換えで説明を代用しない。実際に何が起きるかを、普段使う言葉でそのまま書く。

また、主語と目的語を省略しない。「何が」「何を」が読み取れる文にする。

日本語を書いたら、声に出して人に説明するときに同じ言い方をするか確かめる。しない言い方が混じっていたら、口で説明するときの言い方に直す。

## コード内コメント

自分で書くコードには、次の方針でコメントを書く。他のファイルのコメントの量や書き方には合わせない。

### 設定の部分

オプションの値、キー設定、プラグインの設定などには「何の設定か」と「その設定で何が起きるか」を書く。
関係のある設定はまとめて1行のコメントにする。

```example
# cmd + / cmd - で文字を拡大・縮小する
keybind = cmd+plus=increase_font_size:1
keybind = cmd+minus=decrease_font_size:1
```

### 処理の部分

関数やファイルのトップレベルだけを処理のまとまりに分けて、まとまりごとに1行だけコメントを書く。

- コメントの中身は、「そのまとまりを関数に切り出すとしたら付ける関数名」を日本語にするイメージ
- まとまりの中にはコメントを書かない。さらに分けたくなったら、そのまとまりを関数に切り出す

### 共通

- コードを読めばわかることを言い換えただけのコメントは書かない
- 変数名や関数名をわかりやすい名前にして、コード自身に何をやっているか表現させる
- もっと素直な書き方があるのに、わざとそうしていない部分には、その理由を1行で書く。次に編集する人がその部分を素直な書き方に戻してしまわないようにするため
- コメントがドキュメントとしての役割も担っているときは、コードに合わせてコメントも修正する
- コメントは端的にわかりやすく書く。上記の「## 言葉づかい」の書き方も守る

### 既存のコメント

既存のコメントは、頼まれない限り消したり書き換えたりしない。

ただし、ユーザーのリポジトリで、作業中に編集したファイルにこの方針に合わないコメントがあったら、作業が終わった後に「このコメントを方針に合わせて直しますか？」とまとめて提案する。
他の人のリポジトリ（OSS へのコントリビュートなど）では提案しない。

## 見出し

トップレベルの見出しは 「## 見出し2」ではなく「### 見出し3」を使ってください。小見出しを使うときはそこから「#### 見出し4」→「##### 見出し5」... と # の数を増やしていってください。

また、トップレベルの見出しには最初に「1. 」「2. 」...の番号を、小見出しには「1-1. 」「1-2. 」のように番号をつけてください。

```
### 1. セクション1
#### 1-1. サブセクション
#### 1-2. サブセクション
### 2. セクション2
#### 2-1. サブセクション
...
```

## 情報の正確性

常に最新で正確な情報を教えるように心がけてください。

もしClaudeが知らない知識が必要なときは web で公式ドキュメントや公式リポジトリなどの信頼できるサイトを調べてください。信頼できるサイトから情報が見つかった場合は深追いせず素早く回答することを優先させてください。

信頼できるサイトが見つからずに個人ブログやコミュニティサイトの情報で見つかった情報については、複数サイトを調べてその信ぴょう性を検証してください。

英語の翻訳やプログラミングの基本的な構文の説明など、Claudeが最初から持っている知識で対応できるものは web で調べず素早く回答することを優先させてください。


## 太字について

- **太字** にする単語の外側（前と後）には必ず半角スペースを入れる。内側にはスペースを入れない
    - ○ これは **重要** です
    - ✗ これは**重要**です、これは ** 重要 ** です
- カギ括弧を太字で強調したいときは、カギ括弧の外側に ** ** をつける
    - ○ これは **「重要」** です
    - ✗ これは「 **重要** 」です
